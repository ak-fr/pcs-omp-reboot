# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A parallel meet-in-the-middle (MITM) attack framework for symmetric ciphers: given `f` and `g`, find **claws** (`f(x0) == g(x1)`) or **collisions**. Header-only C++17 in `include/`; `examples/` holds runnable drivers per cipher (double-Speck64 — the current focus, double-DES, double-AES, SHA256).

**Two engines run today, both on the Router alone** (`include/router/`) and sharing no transport with each other. Both run one MPI rank per node and one OpenMP team of `1 + dicts_per_node + producers_per_node` threads per rank: thread 0 is the Router's service thread, the next ones are receivers owning a dictionary shard each, the rest are senders. Both end a round with `Router_Reset` — the barrier the algorithm needs, its two team barriers and its `MPI_Barrier` inside it — and an epilogue of one `MPI_Allgather` of the node's tallies, its `Router_Stats` and its golden pair, from which every node reads the same verdict. **The Router owns placement in autopilot mode**: both engines pass `ROUTER_GROUP_AUTO`, never pin a thread and never query hwloc.

**The direct engine.** One header, `direct.hpp`, entry points `mitm::direct::claw_search(pb, nbytes_memory, opts, prng)` and `mitm::direct::collision_search(...)`. The exhaustive meet-in-the-middle: `ceil(2^n / (fill * w))` rounds of two phases, `f` fills the distributed dictionary on a chunk of the domain, then `g` probes it on the whole domain, matches resolved by the dict threads themselves, nothing dropped. One phase is one Router round, so `Router_Reset` is the FILL→PROBE barrier. Its round sequence is deterministic, so it needs no control channel at all, and "no solution" is a proof.

**PCS**, rebuilt on the Router (`include/pcs/`), entry points `mitm::pcs::claw_search(...)` and `mitm::pcs::collision_search(...)`. Van Oorschot-Wiener parallel collision search: the problem becomes one random function `x -> f(mix(i, x))` of its range onto itself, a round is one version `i` of it, and the walkers walk trails whose distinguished points fill a dictionary of endpoints. A dictionary hit is **not** resolved where it is found — walking two trails costs far more than a probe — so it is handed to a walker paired with that dict thread, over one bounded queue per dict thread. A round ends on a count no node holds (`beta * w` distinguished points over all the nodes), so PCS keeps a **controller on rank 0** and a control channel of three tags to reach it; it is a Monte-Carlo search, and "not found" is never a proof. The old core it used to sit on (`engine.hpp`, `comm.hpp`, `controller.hpp`, `spsc.hpp`, `placement.hpp`) is **gone**, along with the sequential and "vector sequential" engines deleted long before; a single rank with one walker and one dict thread is the degenerate sequential case.

## Build

```bash
cmake -S . -B build && make -C build
```

- C++17, compiled with `-march=native` — binaries are **not portable across CPU generations**, so on a cluster build on the same arch as the compute nodes. The SIMD path (AVX-512 / AVX2 / scalar) is selected by `#ifdef __AVX512F__ / __AVX2__` guards in `include/types.h` that `-march=native` triggers; the `config/*.cmake` probes set `HAVE_*` vars that are currently **unused**, and `config/neon.*` isn't wired into the root `CMakeLists.txt`.
- **No `CMAKE_BUILD_TYPE` / `-O` flag is set and `NDEBUG` is off**, so default builds are unoptimized with live `assert()`s. Keep this in mind before trusting benchmark numbers.
- Only the MPI **C** API is used, so `find_package(MPI REQUIRED COMPONENTS C)` and the drivers link `MPI::MPI_C`.
  Don't ask for the `CXX` component: it is not the C++ bindings (that is `MPICXX`), it is FindMPI probing the
  `mpicxx` wrapper, which some clusters ship broken or not at all — a spurious `missing: MPI_CXX_FOUND`.
- Requires: **MPI**, **OpenMP**, **OpenSSL** (dev headers — the DES example self-checks against it), **hwloc 2.x** (dev headers, `libhwloc-dev`): it places the threads over the NUMA nodes and is a hard requirement with no fallback. If CMake can't find it, `module load hwloc` or `HWLOC_ROOT=/path cmake ...`.
- **{fmt}** is vendored in `fmt/` and built from source (`add_subdirectory`), so a fresh clone needs `git submodule update --init` before CMake will configure. The reports format with `fmt::print`; `human_format()` in `tools.hpp` returns a `std::string`.
- Binaries land in `build/examples/`. After changing CMake files, a clean rebuild may need `rm -rf build`.
- `examples/CMakeLists.txt` defines one `mitm_example(name [extra sources])` function; every driver links MPI + OpenMP + Threads + hwloc + fmt the same way.

## Run

All drivers share one option parser (`examples/driver.hpp`, `--help` lists everything). **`--ram` is mandatory** for the demos (human units, e.g. `--ram 4G`): the search entry points take the byte budget per node as an explicit argument, and the *library* aborts on 0 — `driver.hpp` only parses the flag, it checks nothing. **`--benchmark`** measures the problem's f/g rate instead of searching and exits, so it needs no `--ram`: there is one driver per problem, no separate bench binary. `--engine` accepts `direct` (the default) and `pcs`; `--fill` is the direct engine's dictionary fill ratio (default 0.5) and `--prefetch` how many points its dict threads hold between `Router_Pop` and the shard with their slot prefetched (default 8, 0 disables it), `--difficulty` / `--alpha` / `--beta` / `--dp-len-bits` are PCS's. Every driver's exit status says whether the golden pair was found.

```bash
mpirun -np 4 --bind-to none build/examples/double_speck64_demo \
    --n 32 --ram 4G --dicts-per-node 2 --producers-per-node 30
```

Topology: **one MPI rank per node**, `MPI_THREAD_FUNNELED`, and **the Router decides where every thread runs** — it pins them, forms its groups and prints both the planned and the measured layout itself. `--dicts-per-node` and `--producers-per-node` (0 == fill the inherited affinity mask) size the team; producers default to filling the mask, hence `--bind-to none`. `--no-bind` hands `opts.router.pin = false` to the Router, which is what two ranks sharing a host need (it refuses to pin overlapping masks). `--cache-level` and `--group` are the Router's group knobs, `--block`, `--swc`, `--n-recv`, `--inbox`, `--credit` its transport knobs; `include/router/common.hpp` documents all of them, and the same flags exist in `examples/router_driver.hpp`. Other topologies are testable on a laptop with `HWLOC_SYNTHETIC="node:1 l3:4 core:4 pu:1"` set on the *application* (`mpirun ... env HWLOC_SYNTHETIC=... build/examples/...`), not on `mpirun`, whose own mapper would then see the fake machine. `--nrounds` bounds the round count so a search can report "not found" instead of running to exhaustion (for PCS, which never exhausts anything, it is the only way to make it give up). On a CEA/TGCC-style cluster the launcher is `ccc_mprun` under an `MSUB` batch script (`tgcc.sh`).

Quick smoke test, 66 rounds of two phases over 2^20 preimages (under a second; `--nrounds 3` makes it give up instead, and exit nonzero):

```bash
mpirun -np 1 --bind-to none build/examples/double_speck64_demo --n 20 --ram 256K \
    --producers-per-node 4 --dicts-per-node 3
```

Two ranks on the one laptop, unpinned (8 spinning threads in all):

```bash
mpirun -np 2 --bind-to none build/examples/double_speck64_demo --n 20 --ram 256K \
    --producers-per-node 2 --dicts-per-node 1 --no-bind
```

`sha2_claw_demo`, `sha2_collision_demo` and `double_aes_demo` have `vlen == 1` (they define no `vlen`, so they inherit the abstract class's 1), hence they exercise the scalar path rather than the problem's `vfg` — and for PCS, its `Lanes` machine with a single lane; `sha2_collision_demo` is the only one that exercises either engine's `CollisionWrapper`.

PCS needs about `2^n / w` versions of the function to single out one claw among the `2^n` a problem of that size has, so a smoke test wants a difficulty worth having: **a dictionary that holds a large share of a small domain drives `theta` towards 1**, where every point is distinguished, trails are one step long and the search degenerates into sampling start points. `--n 20 --ram 256K` over 3 shards puts `1/theta` near 2.3, which is the regime the `pcs_*` tests use; the same `--ram` at one shard doubles `w` and halves the difficulty again.

```bash
mpirun -np 1 --bind-to none build/examples/double_speck64_demo --n 20 --ram 256K --seed 1 \
    --engine pcs --producers-per-node 4 --dicts-per-node 3
```

## Layout & conventions

`include/` holds three things: the two engines (`direct/` and `pcs/`, each a directory of its own), the Router (`router/`), and what they all share.

- `types.h`, `tools.hpp`, `problem.hpp` — SIMD types; PRNG/timing/hashing/formatting and `Point` (the two-word wire unit the Router carries: routing key + payload); the abstract problem interface.
- `parameters.hpp` — **`Options` and nothing else**: every user knob, all with a working default, no methods, no MPI, plus one `Router_Opts router` member holding the Router's own. A driver fills it and hands it to an entry point, which derives its parameters once.
- `direct/` — **the direct engine**, `namespace mitm::direct`, one header per concern with `direct/direct.hpp` the umbrella include, mirroring `router/`. `params.hpp` (`direct::Params` with the domain, `per_round`, `n_rounds`, `check_bits` — nothing about the team, which is the Router's to answer; the phase enum and its tag; the 4 counters and the round record's layout), `shared.hpp` (`Tally` and `Shared`, the tallies plus the golden pair and the verdict), `wrappers.hpp` (the two problem wrappers, `ClawWrapper` and `CollisionWrapper`: `veval()`, `good()`, `self_test()`), `dict.hpp` (the linear-probing `DirectDict`, a plain container whose `probe` returns the run's candidates in a caller-owned vector, and the dict thread that inserts in `FILL` as the points come and probes-and-resolves in `PROBE` through a ring of `--prefetch` points whose slots it prefetches as they come), `producer.hpp` (the producer that enumerates its piece of the domain and pushes), `engine.hpp` (the service round, the epilogue, all the printing, `run()` and `direct::claw_search` / `direct::collision_search`).
- `pcs/` — **PCS**, `namespace mitm::pcs`, one header per concern with `pcs/pcs.hpp` the umbrella include, mirroring `router/`. `params.hpp` (`pcs::Params` — the dictionary's geometry and the round's quota, nothing about the team, which is the Router's to answer — `Header`, the 14 counters, the round record, the four tags), `shared.hpp` (`CollisionCandidate` / `CollisionQueue`, the HyperLogLog and `RoundStats`, `Tally`, `Shared`, and `assign_receivers` — which dict thread each walker resolves for), `dict.hpp` (`PcsDict` and the dict thread's round), `walker.hpp` (`retire_collision`, the `Lanes` — the walker's machine: `vlen` lanes each running one instruction to its end, a trail or a collision's MEASURE/ALIGN/MARCH, a lane taking the next instruction where its own ends, a pending collision before a fresh trail, so no lane is ever idle and there is no free list and no live count — and `walker_round`), `control.hpp` (`Control`: the controller on rank 0 and every node's end of the channel), `wrappers.hpp` (the three problem wrappers), `engine.hpp` (the printing, the service round, the epilogue, `run()` and the two entry points).
- `router/topology.hpp` — **the hwloc primitives**: `pin_to_cpu`, `lowest_shared_cache_level`, `topology_of_cpus`, `cores_by_domain`, `emptiest_core`, in `namespace mitm`. The one file that touches hwloc, and `router/placement.hpp` is its only user. Neither engine calls any of it — placement is the Router's.

**The code is the specification.** There is no separate protocol document any more: the headers' head comments say what each round, message, barrier and channel does, and a change to a round's lifecycle, the point format, the routing, a barrier, the control channel or the loss semantics updates the comment of the header it touches in the same commit.

`examples/driver.hpp` is *not* part of the library: it is the shared CLI + MPI startup for the drivers (`mitm::init`), and lives next to them. `mitm::Driver` holds the knobs that are the driver's own rather than the library's — `--ram`, `--n`, `--seed`, `--engine`, `--benchmark` — with a default each, and `mitm::benchmark_and_exit(pb, drv, opts)` is the one line every driver calls once its problem is built: it returns at once unless `--benchmark` was given. `examples/benchmark.hpp` is `benchmark()` alone, what that call runs: the problem's f/g rate from `Options` and a problem, no RAM, no engine of its own — a claw problem alternates f and g then `vfg`, a collision problem iterates f alone then `vf`. It builds no team, so it runs `producers_per_node` OpenMP threads itself (0 meaning every CPU the affinity mask allows), each walking its own dependent chain, to measure what concurrent producers do to each other's cache and memory traffic rather than one isolated thread.

**The Router** (`include/router/`, a directory of one header per concern, `router.hpp` the umbrella include; the headers' comments are its specification) is **the transport both engines run on**: an MPI-style procedural interface around one RAII handle, the `Router_thread` that `Router_Init(role, group, comm, tag, opts)` returns to each thread by value (collective over every thread of every node, the same arguments everywhere **but `group`**, `ROUTER_DEFAULT_OPTS` for the defaults; the caller keeps it named for the team's whole life). **The Router owns placement**: by default it pins the threads and forms G groups, a group being senders and receivers in one cache domain, at most `opts.group_size` cores each — the receivers then the senders are round-robined over the domains into the least-filled group. The service thread keeps a whole core to itself: nothing is ever placed on its SMT siblings, and a team that then no longer fits the mask is refused. The interface's queries are `Router_group` and `Router_num_groups` for the plan, and `Router_size(rt, role, scope)` / `Router_rank(rt, scope)` for the team's shape — the threads of a role, and the caller's rank among those of its own, on the node (`ROUTER_NODE`) or over all nodes (`ROUTER_GLOBAL`). PCS pairs each walker with a dict thread of its own group by reading `Router_group` across the whole team and matching on the value itself (`include/pcs/shared.hpp`'s `assign_receivers`), not through a Router-provided pairing call. **Neither engine stores a count or a rank of its own**: `direct::Params` and `pcs::Params` hold the dictionary's geometry and the round count or quota, and every thread asks the Router where it needs the shape. Placement beyond the group — which CPU, which cache domain, which NUMA node — is printed in the verbose banner but not exposed to the caller at all. `opts.pin = false` leaves the CPUs to the caller and groups by worker index; a per-thread `group` color takes the caller's groups à la `MPI_Comm_split`. When pinning it **refuses** a mask too small for the team or one shared with a co-hosted rank, so two ranks on one host need `--no-bind`. Every round call takes the handle: `Router_Push`, `Router_Close`, `Router_Pop`, `Router_Test_drained` a worker's own (no `omp_get_thread_num()` on the hot path), `Router_Progress`, `Router_Test_quiescent`, `Router_Stats` the service thread's; `Router_Reset` is collective over the team (its two team barriers and the `MPI_Barrier` are inside it, so the caller writes none). The node's shared state (`Router_node`) is internal: thread 0's handle owns it and deletes it when it dies at the end of the parallel region, so everything is gone before `MPI_Finalize` with no scoping needed. It routes points from sender threads to globally numbered receiver threads across ranks: senders stage into shared per-destination blocks through a private write-combining line (PROBLEM.md §9), with **non-temporal stores** (`router_stream_copy`), so a block is never fetched into the writer's cache — measured 2.1x on a 256-core EPYC, where a plain `memcpy` pulled every staged line in from DRAM, half of it across the sockets; a block is a message: the service thread (thread 0, all MPI) sends it from block memory, receives into block memory and hands blocks to the receivers by id (the pool is first-touched by every thread of the team, a slice of blocks each, so its pages spread over the rank's NUMA nodes instead of all landing on the service's), copying nothing at all: `Router_Pop` reads the delivered blocks in place, one point at a time, and gives each back to the pool once read through. **Nothing is ever dropped**: a sender that finds no room waits for one (the lossy mode, measured worthless and prone to a latching collapse, was removed). Free blocks live in a bounded MPMC ring of block ids (Vyukov): a receiver pushes by a `fetch_add` ticket and never fails, a sender or the service pops a batch by one CAS and fails cleanly when empty. It shares only `tools.hpp` (for `Point`) and `topology.hpp` with the rest of the tree; its `RouterRing` is a minimal, non-templated SPSC ring of its own, on purpose. The parts: `router.hpp` (the umbrella include), `ring.hpp`, `common.hpp` (constants, `Router_Opts`, `Router_thread`, `Router_node`), `placement.hpp` (`RouterPlacement`), `connect.hpp` (`Router_Init`, `connect`, the queries), `workers.hpp` (the free ring, the sender and receiver paths), `service.hpp` (the service thread). `examples/router_test.cpp` is its test suite (`ctest --test-dir build`, or `mpirun -np 2 --bind-to none build/examples/router_test --senders 3 --receivers 2 --no-bind`; `--test NAME` for one, `placement` drives `RouterPlacement` alone on synthetic machines, `groups`/`colors` cover the group paths through a real team), `examples/router_bench.cpp` its benchmark (`--help`); both take their options from `examples/router_driver.hpp`. The laptop has 8 physical cores: keep its runs to 8 spinning threads in all (np 1 pins: `--senders 4 --receivers 3`; np 2 `--senders 2 --receivers 1 --no-bind`; np 4 needs 12, correctness only).

Other conventions:

- A new cipher = a `*_problem.hpp` implementing `f`, `g`, domain against the abstract interface + a ~20-line driver.
- Vectorization is opt-in per problem: set `vlen` and provide `vfg`/`vf` using `v32`/`v64` from `types.h`. **With `vlen == 1` there is no `vfg` to provide** — both engines' wrappers call `f`/`g` directly under `if constexpr`. The abstract problem classes deliberately *declare* `f`/`g`/`vfg` without defining them, so a missing member is a compile or link error rather than a function that silently returns 0 (which is what used to happen).
- Cipher primitives are C (`sha256.c`, `aes.c`, `usuba_des.cpp`); the framework is C++17.
- Notation: `n` = domain bits, `m` = range bits, `w` = dict slots, `theta` = distinguished-point proportion, DP = distinguished point.
- **Where state lives**, per rank, the same in both engines: private to a thread and touched by nobody else — its Router handle, a dict thread's shard and (PCS) its collision queue, a producer's buffers, a walker's HyperLogLog registers and lanes, thread 0's stats and record arrays and (PCS) its `Control` → a local of that thread's scope; shared by the team — the tallies, the golden pair, the verdict → the one `Shared`, built before the team. `Shared::tally[tid].ctr[]` is one `u64[N_COUNTERS]` per thread on a cache line of its own, **plain, never atomic**: its owner writes it and thread 0 reads it after `Router_Reset`'s first team barrier, which is what makes the writes visible. PCS's service thread also reads them *unsynchronised* mid-round for its progress report, which is why the report and the live line are approximate. The exceptions are the golden pair (a mutex and an atomic flag, since any dict thread or walker may find one at any moment) and PCS's two hot-path flags, `round_over` and each dict thread's `done`.
- **Per-thread objects are built by their owning thread**, right after `Router_Init` — i.e. once the Router has pinned it. A dict thread's shard is the case that matters: its zero-fill is the NUMA first touch of every page, so don't move it before the team or into a constructor called elsewhere. PCS builds its collision queue there too, and a walker its 64 KB of HyperLogLog registers, publishing a pointer to them for thread 0 to merge — which costs PCS one startup barrier the direct engine does not need. Deliberately left for later: a NUMA-affine parallel flush of the shards between rounds, and a generation bit in dictionary entries to skip the flush altogether (which would change the "empty at the start of a round" guarantee).
- **Don't commit or hand-edit `build/`** — local, gitignored, out-of-source.

## Gotchas

- **`is_good_pair` must be symmetric for a collision problem**, as `problem.hpp` says. `SHA2CollisionProblem`'s was not, and that alone was the long-standing "`pcs::collision_search` plateaus for some seeds": the direct engine enumerates the whole domain and meets the pair in both orders, so it never noticed, while PCS retires a collision in whichever order it located it and had its golden pair rejected half the time. Fixed in the problem, not worked around in the wrapper.
- **PCS refuses a dictionary shard with no walker to resolve for it**, because that shard's collisions would all be dropped. `--dicts-per-node > --producers-per-node` is refused before the team is built; the group-shaped case (a Router group holding two receivers and one sender, say) is caught by thread 0 after the startup barrier and calls `MPI_Abort`, naming the knobs. Reproduce either with `HWLOC_SYNTHETIC="node:1 l3:2 core:4 pu:2"` and `--dicts-per-node 3 --producers-per-node 3`.
- **PCS's collision queue is the one lossy thing in the tree, and it has to be.** A full queue truncates the run and tallies `DROP_COLL`; it cannot block, because `Router_Push` spins waiting for a free block, so a dict thread blocked on a queue whose only consumer is a walker inside a push would deadlock the pair. Nothing else is dropped: `round_over` makes a walker `Router_Close` **first** — which is what lets its dict thread reach `Router_Test_drained` and set `done`, so closing last would deadlock — and then run the machine dry, resolving the queue out and stepping `4 * dp_max_it` more cycles (the worst case for one candidate: a re-walk per unknown length, then `len0 + len1` for the align and the march at two cycles a step) before asserting every lane is back on a trail.
- CTest runs the Router's tests and both engines' (`router_np1/2/4`, `direct_np1/2`, `pcs_np1/np2`, `pcs_collision`). The engines have no unit tests beyond that: the demos plant a golden pair and `assert()` their way to it, and their **exit status** is whether they found it — which is what the `direct_*` and `pcs_*` tests check. With Open MPI, CMake defaults `MPIEXEC_PREFLAGS` to `--bind-to none`, or a rank's whole team lands on one core.
- **The direct engine's live one-line display is rank 0's own node**, read from its tallies without synchronisation and scaled by the node count; PCS's comes from the progress reports, so it covers every node but lags them. Both are approximate on purpose. The round report comes from the epilogue's `MPI_Allgather` and is exact. Don't expect the two to agree to the unit.
- **Both live lines end with the Router's verdict on what limits the flow** (`Router_Bottleneck`): the shares of the round the senders spent waiting for a free block or closed, the receivers had nothing to pop and the service in turns that moved something, then `senders` (production-bound), `receivers` (the dict threads), `service/network` (both wait; a busy share near 100 % is the service's CPU, well below it the wire or the credit) or `balanced`, by a 5 % threshold. The round report's `LIMITED BY` line is the same from the summed records, exact. The waits are wall-clock (`wtime()`), timed at their ends only, and the drain tail counts as receiver wait: read it on phases long against their closure. Round 0's FILL says `receivers` while the dict threads still touch their shards, which is true.
- Neither engine has **an early exit inside a round**: the direct engine stops at the end of the phase in which a golden pair turns up (cutting a phase short would need a control channel of its own and can save at most one phase), and PCS ends the round through `TAG_SOLUTION` at the next control turn.
- `Router_Pop` reads each delivered block **in place** and gives it back with its last point; the whole-block `Router_Grab` / `Router_Release` pair is gone (2026-09-16: nothing used it). A block may hold fewer than `block_points` points, and a receiver that stops popping before `Router_Test_drained` says so both prevents quiescence and aborts in `Router_Reset`.
- In lossless mode, raising `--credit` or lowering `--inbox` moves more of the Router's pool into paths that can stall; a multi-node deadlock was found and fixed that way once (`FINDINGS.md`, session 8). Retest multi-node after touching `--n-recv`, `--credit` or `--inbox`.
